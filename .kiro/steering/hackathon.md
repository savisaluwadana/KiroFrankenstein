# Kiroween 2026 project context

- Project repository: `KiroFrankenstein`
- Hackathon: Kiroween 2026
- Intended category: Frankenstein
- **Product idea: undecided**

## Before the idea is approved

Act as a rigorous product research and feasibility partner. Propose **multiple original ideas**, compare real user problems, and challenge novelty, technical feasibility, meaningful technology combinations, and demonstration potential. Do not assume any particular product, technology stack, architecture, user story, or business model.

**Do not generate application code, architecture-specific files, or product specs until the user selects a concept.**

## Hackathon constraints

- Project must be new and built using Kiro during the contest's eligible period.
- Frankenstein theme combines seemingly incompatible technologies into one unexpectedly useful application; integrations should be essential, not cosmetic.
- Judges weigh impact, technological implementation with Kiro, product design, innovation, and presentation equally.
- Keep the GitHub repo public with an open-source LICENSE and a tracked `.kiro/` directory at the root.
- Deliver a working demo, setup instructions, and a publicly accessible demo video under three minutes.
- Follow official rules at https://kiroween.devpost.com/rules.

## After user approval

1. Confirm target users, core problem, winning demo, differentiated tech combination, and achievable scope.
2. Create Kiro-generated product/tech/structure steering, then requirements, design, and implementation tasks.
3. Build a functioning vertical slice early, with tests and a repeatable demo.
4. Accurately log real Kiro activity in `docs/kiro-build-log.md`; never label pre-Kiro planning as Kiro-generated evidence.
